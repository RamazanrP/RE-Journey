# Orbit Fold — Write-up (EN)

## 1. Challenge Overview

In this challenge, we are given an ELF binary named `challenge` and an `encoded_flag.txt` file. First, we inspect the strings:

```bash
strings challenge
```

Two strings immediately stand out:

```text
flag.txt
encoded_flag.txt
```

## 2. `main` Function

At the beginning of the program, we can see that the current time is retrieved:

```c
tVar4 = time((time_t *)0x0);
srand((uint)tVar4);
```

The important part here is that the value returned by `time(NULL)` is passed directly to `srand()`.

This means that the random values are not completely fixed. Since the time changes each time the program runs, the initial state of the PRNG changes as well.

The program then opens two files:

```c
std::ifstream::ifstream(local_228, local_468, 8);
std::ofstream::ofstream(local_428, local_448, 4);
```

By connecting these calls with the strings we found earlier, we can identify them as:

```text
flag.txt           → input
encoded_flag.txt   → output
```

## 3. File Reading Loop

The program reads `flag.txt` one character at a time:

```c
while (true) {
    ...
    std::istream::get(...);
    ...
}
```

The purpose is to encode each character individually.

Inside the loop, we find:

```c
iVar3 = rand();
```

The decompiler then shows the following somewhat confusing expression:

```c
*local_480 =
    (char)iVar3 +
    (char)(iVar3 / 10) * -10 +
    1U ^
    (byte)local_481;
```

After examining the assembly, we can identify this as:

```c
rand() % 10 + 1
```

Therefore, the operation can be simplified to:

```c
key = rand() % 10 + 1;
encoded = key ^ input;
```

So each character from `flag.txt` is XORed with a value between `1` and `10`.

## 4. Structure of `encoded_flag.txt`

At this point, it is important to inspect not only the code but also the generated file itself.

```bash
xxd -g 1 encoded_flag.txt
```

The output shows repeating 4-byte blocks:

```text
70 00 01 00
23 00 01 00
7c 00 01 00
3e 00 01 00
...
```

The code in Ghidra explains this structure:

```c
local_480[0] = 0;
local_480[1] = 0;
local_480[2] = 1;
local_480[3] = 0;
```

Only the first byte is then modified:

```c
*local_480 = encoded;
```

Finally, the program writes **4 bytes**:

```c
std::ostream::write(..., 4);
```

Therefore, the file structure is:

```text
[encoded][00][01][00]
[encoded][00][01][00]
[encoded][00][01][00]
...
```

Since the file is 68 bytes long:

```text
68 / 4 = 17
```

17 characters were encoded.

Therefore, we take the first byte from every 4-byte block as the ciphertext:

```text
70 23 7c 3e 71 77 3a 56 51 72 6f 64 36 6c 38 7e 09
```

## 5. The Hint in the Challenge Title

At this point, we know the encoding algorithm, but we still need to reproduce the values generated by `rand()`.

The challenge title is:

```text
Time
```

The author also provided the following hint:

```text
Take this as a hint and make sure to read the challenge title

Time 16/2/2026 3:30:0 Amman
```

The word `Time` is directly related to the `time(NULL)` call we found earlier.

We can use the given time and the `Asia/Amman` timezone to obtain the corresponding Unix timestamp:

```bash
TZ=Asia/Amman date -d "2026-02-16 03:30:00" +%s
```

The result is:

```text
1771201800
```

Therefore, we can reconstruct the seed used by the challenge:

```c
srand(1771201800);
```

## 6. Reproducing the `rand()` Sequence

We can reproduce the random sequence using the same libc PRNG:

```python
import ctypes

seed = 1771201800

libc = ctypes.CDLL("libc.so.6")
libc.srand(seed)

for i in range(17):
    r = libc.rand()
    key = r % 10 + 1
    print(f"{i:2}: rand={r:10} key={key}")
```

This gives us the following key values:

```text
10 8 7 9 8 7 9 9 1 7 1 10 7 2 1 3 3
```

## 7. Decoding the Ciphertext

The program performs:

```c
encoded = key ^ plaintext;
```

Since XOR is reversible, we can recover the plaintext using:

```text
plaintext = encoded ^ key
```

Ciphertext:

```text
70 23 7c 3e 71 77 3a 56 51 72 6f 64 36 6c 38 7e 09
```

Key:

```text
10 08 07 09 08 07 09 09 01 07 01 0a 07 02 01 03 03
```

We can manually verify the first few bytes:

```text
0x70 XOR 0x0A = 0x7A = 'z'
0x23 XOR 0x08 = 0x2B = '+'
0x7C XOR 0x07 = 0x7B = '{'
```

Applying XOR to all bytes gives:

```text
z+{7yp3_Punn1n9}
```

## 8. Conclusion

The overall logic of the challenge can be summarized as follows:

```text
Time hint
    ↓
16/02/2026 03:30 Amman
    ↓
Unix timestamp
    ↓
1771201800
    ↓
srand(1771201800)
    ↓
rand() % 10 + 1
    ↓
key stream
    ↓
ciphertext from encoded_flag.txt
    ↓
ciphertext XOR key
    ↓
z+{7yp3_Punn1n9}
```

The main idea of the challenge is not only identifying the XOR operation, but also connecting the challenge title and the author's time hint to the `time(NULL)` call used to seed the PRNG.
We then extract the actual ciphertext from the 4-byte blocks in `encoded_flag.txt` and reproduce the same key stream to recover the flag.


Burada önemli nokta `time(NULL)` ile elde edilen değer `srand()` fonksiyonuna gönderiliyor.

## 3. Dosya Okuma Döngüsü



